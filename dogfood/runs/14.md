# Run 14 — 2026-07-03 (k=1 full-grid regression; validates the plugin/mcp "diet" trimming commits)

A **k=1** smoke/regression run of the full grid — **12 tasks × 3 solvers = 36 students** (+36 verify
agents) — to confirm the tail of `feature/absorb-carve-diet` didn't regress agent ergonomics. Since
run 13 the branch landed five "diet" commits that shrink exactly the surface this tournament exercises:

```
7ca2d1410af8 plugin: Trim the operator prompt to its delegation missions
00f2f8264323 plugin: Dedupe the skills and teach the absorb/carve recipes
afa3a3edf20d mcp: Trim tool descriptions and the INSTRUCTIONS manual
4be4fc8edb9b mcp: Cap show_commit and session_diff diffs and add a paths filter
eb26a34a9cf7 mcp: Default list_history to a header-only overview
```

**MCP surface under test:** this checkout's plugin install (`~/.local/share/commedit-marketplace/plugin`)
is a live symlink straight at the repo's `plugin/` dir (no snapshot/`plugin update` staleness risk), and
the two running `commedit-mcp` server processes were checked by PID ancestry — this session's server
(spawned at the session's `claude` launch) is the fresh one, its binary `md5sum`-identical to a
just-rebuilt `target/release/commedit-mcp`. So the students exercised the tuned prompt/skills/tool
descriptions and the current engine exactly as they sit at `7ca2d1410af8`, not a stale cache.

Orchestrated via the unmodified `dogfood/workflow.js` (only `K` edited 3→1 for the run, reverted after).
72 agents at up to 16-way concurrency, total workflow wall-clock ~8m19s, 0 agent errors, 0 empty results.

## Result: 36/36 oracle-PASS, post-settle re-check clean, fsck clean

Every cell passed `verify.sh` on first completion. Per README's mandatory ref-race guard, I re-ran the
oracle across all 36 worktrees again after the run settled — still **36/36**, no silent reverts. Also
spot-checked the two structural invariants no PASS/FAIL line captures: T7's merge kept its 2 parents
identically across all three solvers, and T11's sibling branch retained `flag.txt` / dropped
`version.txt` on all three. `git fsck` on the shared common dir showed only expected dangling-object
noise from the rewrites — no corruption.

## Headline: the diet commits introduced no regression

- All 24 MCP students (op+ctl) routed to the right tool on every task, including the harder
  discriminators: **T2** avoided the split-then-revert-to-parent footgun (op and ctl both listed
  `util.txt` at *parent* content); **T7** kept 2 parents through reword+fixup-into-merge; **T9** landed
  as a single atomic `edit_commits` batch for both op (2 calls, 48s) and ctl (7 calls, 53s); **T10**'s
  `abort_rewrite` beat fired before the resolve-and-redo; **T11** opened and addressed the off-worktree
  sibling session correctly on both; **T12**'s `blame_squash_targets` returned the single "Add retry
  helper" candidate for both, with nobody dead-ending on the empty `suggest_squash_targets` route.
- **`list_history`'s new header-only default (`eb26a34a9cf7`) didn't trip anyone up.** Only 7/36 tool
  logs mention an explicit `fields=` — students needing more (T4/T9's identity+date checks, T2's
  content compare) asked for it; nobody misidentified a target off a header-only read. The trim reads
  as a genuine no-op for correctness.
- **git remains by far the slowest, most call-heavy class** (median 138s / 18.5 calls vs op's 59s /
  10.5), consistent with every prior run — non-interactive scripted rebases are still the friction
  point, unrelated to anything on this branch.

## What this run establishes

- **The diet commits are safe to land.** Zero correctness regressions across all 12 tasks and all 3
  solver classes, post-settle re-checked. Tool-description and operator-prompt trimming, the
  `list_history` default change, and the diff-capping/`paths` filter on `show_commit`/`session_diff`
  didn't cost any student a wrong tool call or a misread target.
- **k=1 is a regression smoke test, not a ranking run** — single sample per cell, and per the cost note
  above, not even reliably cost-comparable across runs without a logged effort level. A comparative
  cost claim about the trims needs k≥3 with a *logged* effort level and, ideally, the manual
  per-component `$` recovery this workflow harness still can't do (the same open gap runs 9 and 13
  flagged).
- **Teardown ran clean**: 44 `stress/*` branches + worktrees removed, `rerere` cache cleared.
