# Run 7 — 2026-06-23 (k=2 full grid; ref-race fix verification, gc mitigation removed)

A **k=2** run of the full grid — **11 tasks × 3 solvers × 2 repeats = 66 students** — whose purpose was
to **confirm the ref-write-race fix** (`c6f56ca` *"engine: Scope the unrelated-head backstop to
jj-tracked refs"*). Run 4–6 attributed silent post-completion result reverts under fan-out to a git
`pack-refs`/`gc --auto` race and mitigated it with `gc.auto 0` + `maintenance.auto false`. That commit
re-diagnosed the root cause: `protect_unrelated_heads` was force-restoring **another session's** branch
(never imported by this session) back to *this* session's stale snapshot — a cross-session clobber, not a
git GC race. So this run **rolled back `gc.auto`/`maintenance.auto`** (race *exposed*) and ran the grid at
full 33-way concurrency **twice**, re-checking every cell with the git-only oracle after settle.

**MCP surface under test:** the server was relaunched from the freshly-built binary carrying `c6f56ca`
(marketplace binary mtime 21:54, server start 21:55, both after the 21:38 fix commit; release build byte
size matched). Operator agent + skills byte-identical to the installed snapshot. Teacher on **fast effort
(Opus)**; the operator/control/git students on **Sonnet 4.6** per protocol. Each repeat was an independent
cold spawn; the two repeats of a cell ran serially on its own worktree (reset + `reload_repo` between),
different cells in parallel — so peak concurrent ref-writers was the full 33, the exact race exposure.

## Result: 65/66 oracle-PASS, **zero ref-race reverts in either repeat**

- **Rep 1:** 31/33 clean PASS first-pass; **0 ref-race reverts**. The two non-clean cells were both
  **plain-git self-inflicted**, not commedit and not the race (see findings 2–3).
- **Rep 2:** **33/33 clean PASS**; **0 ref-race reverts**.

Contrast run 6: **4/33 silently reverted** *with* `gc.auto 0` set. Run 7 ran the same concurrency **with the
mitigation removed**, twice, and saw **no revert at all**. The backstop-scoping fix holds; **`gc.auto 0` is
no longer needed**.

## Headline findings

1. **The "ref-write race" was a misdiagnosis; the fix eliminates it.** Scoping
   `protect_unrelated_heads` to `view().git_refs()` (the refs *this* session's jj actually imported) stops a
   session from force-restoring a sibling session's branch to a stale tip. With it in place, 66 cold-spawn
   students at 33-way concurrency and **no gc mitigation** produced **zero** post-completion reverts — where
   run 6 lost 4/33 *with* the mitigation. The earlier "earliest-finisher gets reverted under load" signature
   was the cross-session backstop firing, not `pack-refs` dropping a loose ref. `tests/refrace_repro.rs` is
   the unit-level guard; this run is the end-to-end confirmation.
2. **A plain-git baseline student corrupted the shared fixture base (rep 1, `t5-git`).** Instead of editing
   its own `stress/t5-git`, the student rebased its work and ran `git update-ref refs/heads/stress/base` +
   left a detached HEAD — **moving the shared `stress/base` ref** that every task and `verify.sh` compare
   against. Collateral: several *concurrent* students' self-reported `git diff stress/base` then showed a
   spurious `src/parser.txt` delta, which they rationalized as "pre-existing." The teacher detected the moved
   ref mid-run and restored it; the oracle (run after settle, on the correct base) graded everyone correctly.
   Two lessons: (a) the **plain-git baseline can reach and clobber shared refs** — rep 2 added a uniform
   git-student guardrail ("operate only on your target branch; never touch `stress/base`/other refs"), after
   which `t5-git` solved it cleanly on its own branch; (b) **student self-reports are not authoritative** —
   only the out-of-band oracle is (it caught both the spurious diffs and the one real cleanliness miss).
3. **A student writing its log into the worktree is a real cleanliness failure (rep 1, `t10-git`).** The
   git student appended its `## Tool Log` to the worktree's `README.md`, dirtying the tree — the reorder
   itself was correct, but `verify.sh`'s clean-tree gate (correctly) FAILed it. Rep 2's prompt said to keep
   the log in the reply, not a repo file, and it passed. The only oracle-FAIL of the run, and self-inflicted.
4. **Operator and control are the cheapest solvers; git is priciest (confirms run 6).** Per-cell median `$`
   (per-component Sonnet pricing): **op $0.30 · ctl $0.31 · git $0.34**; per-class totals over 66 students:
   **op $6.94 · ctl $6.84 · git $9.18**, grid ≈ **$23**. Git's cost rides its call volume (many small
   rebase/show steps re-reading a growing bash transcript → large `cache_read`); the MCP students reach the
   end state in far fewer calls. op↔ctl is a wash here (overlapping spreads) — a tie, not a delta. The same
   ordering holds in **wall-clock**: median per-student **op 51s · ctl 58s · git 127s** — git is ~2.5×
   slower (its many sequential rebase steps), and the slowest single cells are all git conflict/rebase tasks
   (T3-git 340s, T1-git 299s, T10-git 234s) where the MCP students finish in ~50–90s.
5. **Fast-effort teacher handled the full grid.** Orchestration of 66 students across two reps, mid-run
   fixture-corruption detection + repair, the oracle gate, and metrics capture all ran cleanly with the
   controlling agent in fast mode.

## What this run establishes / known gaps

- **The ref-race mitigation can be retired.** `gc.auto 0` + `maintenance.auto false` were unset before this
  run and stayed unset; 66 students at peak 33-way concurrency reverted nothing. Keep this config rolled back.
- **k=2 is enough to retire the *race* claim, not to rank close cells.** Two clean concurrent sweeps with no
  revert is strong evidence the race is gone; but k=2 is still thin for *comparative* op↔ctl scoring (use k≥3
  for a ranking claim — the variance protocol stands).
- **Harden the plain-git baseline prompt.** Finding 2 shows the git student can clobber shared refs; the
  rep-2 guardrail ("only your target branch; never touch shared refs / leave detached HEAD") should be the
  **default** git-student instruction in future runs. Likewise "keep the Tool Log in the reply, not a repo
  file" (finding 3). Both are prompt hygiene, not tool bugs.
- **The oracle remains mandatory and authoritative.** It caught the moved-base artifacts and the lone
  cleanliness FAIL that students reported as success — re-run `verify.sh` after settle every time.
