# Run 6 — 2026-06-23 (k=1 full-grid regression; first T11 + fresh MCP surface)

A **k=1 regression smoke run** of the full grid: **11 tasks × 3 solvers (operator, control, git) = 33
students**, the first run to include **T11** (the multi-tenant / cross-branch / off-worktree task) and
the first against the **`verify.sh` git-only oracle** as the correctness gate. Purpose: catch any
agent-ergonomics regression after the recent MCP changes, and confirm the harness runs end-to-end with
the **teacher on medium effort** (the operator/control/git students stay on Sonnet 4.6, per protocol).

**MCP surface under test:** rebuilt from `1af97ac` *"mcp: Omit default and empty response fields to cut
tokens"* — the binary was rebuilt, the plugin re-snapshotted (uninstall+install), and the server
relaunched from the fresh binary before the run (verified by process start time vs binary mtime). The
operator agent + bundled skills were byte-identical to the installed 0.5.0 snapshot. `gc.auto 0` +
`maintenance.auto false` set before launch (run-4 mitigation). Students launched in three fan-outs
(T1–T2, T3–T5, T6–T11) across 33 worktree-bound/off-worktree sessions on one server.

**Result: 33/33 work-correct** (verify.sh exit 0) — *after* re-running 4 ref-race casualties. **No genuine
tool bug surfaced**: every task × solver passes the oracle on a clean (un-raced) run. First-pass was
**29/33**; the 4 failures were all silent **ref-write reverts** (run-4 finding), not logic errors.

## Headline findings

1. **The ref-write race is the dominant failure mode at 33-way concurrency, and `gc.auto 0` is necessary
   but not sufficient** (confirms run-4/run-5). 4 of 33 first-pass cells had their branch ref silently
   reverted *post-completion* — the student's own `pending_status` confirmed `git_head == jj_head` past
   base, then a later concurrent ref-writer on the shared common-dir clobbered the loose ref. **The victim
   is always the earliest finisher in a concurrent batch**: the casualties were `t4-op` (the fastest cell,
   4 calls/~30 s — reverted *twice*, in the main run and again in a 4-way re-run), plus `t3-op`, `t11-op`,
   and a *partial* revert of `t4-ctl`. All four passed once **re-run with ≤1 concurrent writer**; `t4-op`
   and `t4-ctl` needed a strictly **solo** re-run. It hit **MCP sessions and the plain-git baseline alike**
   — three git students (`t2-git`, `t5-git`, `t11-git`) reported their own refs reset mid-operation and
   worked around it with `git update-ref`.
2. **`t4-ctl`'s partial revert looked like an `edit_message` bug but wasn't.** Under load, its final ref
   carried the author fix + `TOKEN_LEN=16` (later ops) but **not** the subject fix (`edit_message`, the
   first op) — a tempting "edit_message doesn't persist" conclusion. Run **solo**, all three edits stuck
   and `show_commit` confirmed them together. So it was a **stale/partial export from the race**, not a
   logic bug — a good reminder to disambiguate race artifacts before filing.
3. **The operator self-recovers from the export stall.** `t10-op` detected `pending:false` while
   `git_head` still sat at base, and **fixed itself with `undo`+`redo`** to force the re-export — landing a
   correct result without teacher intervention (it passed on the first sweep). The 4 casualties simply
   finished before the clobber landed and never saw it.
4. **Operator is the *cheapest* solver per cell despite the prompt tax** — because it takes the fewest
   turns. Per-cell `$` (per-component pricing, Sonnet rates): **op ≈ $0.31 · ctl ≈ $0.43 · git ≈ $0.40**.
   The operator's `cache_create` (skills loaded on demand, few turns) was *lower* than the control's
   (ToolSearch discovery + more turns), and `cache_read` — the dominant component for everyone — was
   lowest for the operator because it re-reads the always-on prefix over fewer turns. Git's cost is driven
   by the largest `cache_read` volume (long bash transcripts re-read every turn) and the highest output.
5. **Medium-effort teacher works.** Orchestration, oracle gating, race detection, and targeted re-runs
   all ran cleanly with the controlling agent on medium effort.

## What this run did NOT change / known gaps

- **k=1**, so these are single samples — a smoke/regression run, not a comparative claim. The op↔ctl and
  (op|ctl)↔git deltas here are directional, not significant (per the variance protocol, a comparative
  conclusion needs k≥3).
- **Ref-race exposure persists.** For the next run consider a per-student common-dir (separate clones) or
  capped concurrency rather than only `gc.auto 0` — the earliest-finisher revert is reproducible under
  fan-out. The oracle re-check after settle (done here) remains mandatory; student self-reports are not
  authoritative.
- `verify.sh`'s subject/content keying held across the rebuild and graded MCP and plain-git paths
  identically — including catching the 4 silent reverts the students reported as success.
