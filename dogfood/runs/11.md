# Run 11 — 2026-07-01 (k=2, operator-only, Sonnet 5 — trimmed operator prompt)

The **first tournament on the trimmed `commedit-operator`** (commit `2754b2c` — system-prompt body cut
from 273→133 lines to shrink per-turn `cache_read`, per the [experiment](../experiments) that preceded
this run and is now retired). **Operator-only**: just the `op` solver, all **12 tasks × k=2 = 24
students**, all on Sonnet 5, with the same per-component `cache_read`/`cache_create`/`input`/`output`
`$` accounting as [run 10](10.md). No control/git solver this round — the question is narrow: *did the
trim hold correctness and cut cost against run 10's baseline?* Same fixture and MCP surface as runs
8–10 (no engine changes).

Orchestrated via a throwaway operator-only variant of the mandatory `Workflow` script (12 cells × k=2,
each cell reset→solve→verify serially, cells in parallel). `$` recovered per run 10's recipe: each
solve student's transcript at `<session>/subagents/workflows/<runId>/agent-<id>.jsonl`, priced at
Sonnet rates (input $3, output $15, cache write $3.75, cache read $0.30 /Mtok).

## Result: 23/24 — one miss, the known T1 reorder quirk

- **T1 landed 1/2.** The failing repeat left `Use format_row` still parented on `Add parser` — the
  operator judged the branch "already correctly ordered" and skipped the reorder. This is the **exact
  Sonnet-5 T1 misjudgment** documented in [run 9](9.md), [run 10](10.md), and **both variants** of the
  prompt-trim experiment (shipped and lean each missed T1 on 2/3 there). It reproduces regardless of
  prompt length → a model judgment quirk on this specific cell, **not caused by the trim**. Post-settle
  oracle re-check confirmed the worktree state (its r2 held the miss), no ref-race revert.
- **Every other task 2/2**, including the tasks the experiment flagged as untested-and-at-risk under a
  trimmed Verification/Boundaries: **T2** (split footgun) 2/2, **T6** (dirty-WC hunk-folding + untracked
  `add_paths`) 2/2, **T11** (off-worktree multi-session cross-branch move) 2/2. The footgun prose folded
  back into the trimmed body (vs the leaner experiment doc) carried its weight — no correctness delta on
  exactly the cells that worried us.
- **T8 caveat (methodology, not the operator):** my run script accidentally defined the T8 cell twice,
  so two T8 students raced the **same** `stress/t8-op` session/worktree concurrently (the "two students
  on one session must not overlap" hazard, §5). One raced cell passed 2/2, the other failed 2/2 with a
  spurious "restore not at tip". A clean isolated T8 re-run (k=2) came back **2/2 PASS** — so the failure
  was the collision, not a tool/model regression. The clean re-run's numbers are used below.

## Reading the delta honestly

- **The full-grid delta (~11%) is smaller than the experiment's 5-task subset delta (24%, $0.327→$0.249)
  — and that's expected, two reasons.** (1) *Different task mix*: the full grid carries the expensive
  conflict/multi-session tail (T11 $0.510, T6 $0.495, T3 $0.470) the 5-task subset (T1/T3/T7/T9/T12)
  under-weighted, and those tasks' cost is dominated by turn count and diff volume, not prompt size, so
  the fixed per-turn saving is a smaller *fraction* of them. (2) *This body is richer than the
  experiment's lean doc* — I folded the T2/T6/T11 footguns back in (133 vs 92 lines), trading a sliver
  of the saving for the correctness insurance that just paid off at 2/2 on all three.
- **`cache_create` came out ~22.6k vs run 10's ~18k** — slightly higher, within noise and dominated by
  the shared MCP tool-schema block (not the doc text), consistent with the experiment's finding that
  `cache_create` is schema-bound. It does **not** erase the `cache_read` win (cc is a one-time cold-spawn
  tax at 1.25× input; the tournament is its pessimistic all-cold case, real reuse amortizes it).
- **Not the k≥3 variance floor.** This is k=2 — a *confirmation* run (does the shipped trim hold?), not
  a fresh ranking. The correctness signal (23/24, single known-flake miss) and the cost direction
  (cheaper, driven by the predicted axis) are consistent with run 10 + the experiment, but a definitive
  rank should still come from a k≥3 full grid with all three solvers. The `op↔ctl↔git` deltas run 10
  drew are untouched here (no control/git solver this round).

## What this run establishes

- **The trimmed operator ships without a correctness regression** across the full 12-task grid, including
  the split / dirty-WC / multi-session cells the experiment could only guess at — all 2/2.
- **The per-turn `cache_read` saving is real on the full grid**, ~11% median cost / ~9% `cache_read` vs
  run 10, at equal call count — the trim did what run 10's finding asked for (a call-count-neutral cut to
  the re-read tax).
- **T1 remains the one flaky cell** (Sonnet-5 reorder-skip judgment), independent of prompt length —
  track it, don't attribute it to the operator.
- **Methodology note for next time:** never let two cells target the same session/worktree — the
  duplicate-T8 collision here is a clean reminder of the §5 same-session hazard. Fixed by isolated
  re-run; the throwaway script is not committed.
- Fixture teardown ran clean.
